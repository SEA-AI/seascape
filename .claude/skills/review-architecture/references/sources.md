# Sources

What each source contributes to the review, and where to read it.

- Martin, single responsibility as "one actor, one reason to change": https://blog.cleancoder.com/uncle-bob/2014/05/08/SingleReponsibilityPrinciple.html
- Martin, open/closed: https://blog.cleancoder.com/uncle-bob/2014/05/12/TheOpenClosedPrinciple.html
- Martin, the clean architecture and its dependency rule: https://blog.cleancoder.com/uncle-bob/2012/08/13/the-clean-architecture.html
- Cockburn, hexagonal architecture (ports and adapters): https://alistair.cockburn.us/hexagonal-architecture/
- Parnas, "On the Criteria To Be Used in Decomposing Systems into Modules", CACM 15(12), 1972, doi:10.1145/361598.361623: https://www.cse.sc.edu/~mgv/csce590f20/ParnasCriteria.pdf
- Ousterhout, *A Philosophy of Software Design*: deep modules, information leakage, temporal decomposition, defining errors out of existence: https://web.stanford.edu/~ouster/cgi-bin/book.php
- Ousterhout and Martin, the debate on small functions: https://github.com/johnousterhout/aposd-vs-clean-code
- Bernhardt, "Boundaries" (values as the boundary between components): https://www.destroyallsoftware.com/talks/boundaries
- Bernhardt, functional core, imperative shell: https://www.destroyallsoftware.com/screencasts/catalog/functional-core-imperative-shell
- Fowler, *Refactoring*, chapter 3 smells (shotgun surgery, divergent change, feature envy, data clumps, primitive obsession, speculative generality): https://martinfowler.com/books/refactoring.html
- Fowler, YAGNI: https://martinfowler.com/bliki/Yagni.html
- Metz, "The Wrong Abstraction": https://sandimetz.com/blog/2016/1/20/the-wrong-abstraction
- Page-Jones, connascence, as catalogued with strength, degree and locality: https://connascence.io/
- Weirich, "Grand Unified Theory of Software Design" (connascence as a coupling vocabulary), talk; summary: https://thoughtbot.com/blog/connascence-as-a-vocabulary-to-discuss-coupling
- PEP 544, structural subtyping with Protocol: https://peps.python.org/pep-0544/
- Rhodes, Python design patterns without Java's ceremony: https://python-patterns.guide/
- Hynek, subclassing in Python redux: https://hynek.me/articles/python-subclassing-redux/
- import-linter contract types: https://import-linter.readthedocs.io/en/stable/contract_types/
